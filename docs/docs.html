Documentation

Everything you need to use pycompile. The same content is available as a man page: man pycompile or pycompile man.

Overview

pycompile is an ahead-of-time compiler that translates a supported subset of Python into C, invokes the platform C compiler, and emits a single standalone native executable. There is no interpreter and no runtime dependency at run time.

It targets small command-line programs and scripts where you want Python's syntax and iteration speed, but a portable native binary as the deliverable.

Two equivalent entry points are installed: the short name pycompile and the long name python_compiler. Anywhere you can write one you can write the other.

Usage

pycompile [OPTIONS] <INPUT> [-- PROGRAM_ARGS...]
python_compiler [OPTIONS] <INPUT> [-- PROGRAM_ARGS...]
pycompile man [--install] [--prefix DIR]

<INPUT> is a .py file, or a directory containing main.py or __main__.py. When it is a directory, pycompile looks for main.py first, then __main__.py, and compiles that file as the entry point.

Options

OptionDescription
-o, --output <PATH>Output binary path. Default: the input name without extension.
--emit-c <PATH>Also write the generated C source to PATH.
--keep-tempsKeep the temporary C build directory.
-r, --runCompile and immediately run the program.
--manPrint the full manual to the terminal.
-h, --helpPrint a usage summary and exit.
-V, --versionPrint version information and exit.

Language support

Compiles to native code

  • Integer, float, string and boolean literals, and None
  • f-strings with format specs and the !r conversion
  • Lists, tuples, sets and dicts, including literal and comprehension forms
  • if / elif / else, while, for-in (with else), break, continue, pass
  • def with default parameters, recursion, and *args / **kwargs parameters
  • Calls with positional, keyword, * and ** arguments
  • Chained comparisons, in / not in, is / is not, and, or, not
  • Slicing and item assignment, augmented assignment
  • The math and sys modules

Not yet supported

These produce a clear compile-time error rather than silent misbehaviour:
  • class definitions, closures and nested scopes
  • try / except / finally, with, raise
  • Decorators, lambda expressions, async and await
  • Modules other than math and sys

Runtime model

The generated C links against a small runtime library that is embedded by the compiler. Values are heap-allocated tagged objects.

Memory is not garbage collected: allocations live until process exit. This keeps the compiler simple and the output small, and is fine for typical short-lived CLI programs.

Runtime errors (for example, a missing argument or an out-of-range operation) print a Python-style traceback to stderr and exit with status 1.

Examples

# Compile a single file
pycompile hello.py

# Choose an output path
pycompile hello.py -o build/hello

# Compile and immediately run
pycompile -r hello.py

# Keep the generated C for inspection
pycompile hello.py --emit-c hello.c --keep-temps

# Compile a project directory
pycompile ./myproject -o myproject

# Pass arguments to the compiled program
pycompile cli.py -o cli -- --verbose file.txt

Limitations

  • No garbage collection: long-running or memory-heavy loops can grow.
  • Closures, classes, exceptions and lambda are not supported yet.
  • % string formatting is not supported; use f-strings instead.
  • sort/sorted support reverse and key but are not fully stable when reverse=True.
